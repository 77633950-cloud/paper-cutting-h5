# 1. AIGC 生成高质量图案的完整实现路径

## 1.1 先明确"目标图案长什么样"——风格锚点

乐清细纹刻纸区别于普通剪纸的 4 个可量化视觉特征，提示词与验收都围绕它们：

| 特征   | 说明              | 画面表现                          |
| ---- | --------------- | ----------------------------- |
| 红白二值 | 红纸镂刻，无渐变无灰阶     | 仅 #C41E3A 红 + 白底（或透明底）        |
| 细镂底纹 | 核心绝技            | 鱼鳞纹、回字纹、斜万字、菊花纹、正字形等几何底纹铺满空白处 |
| 边框构图 | 传统构图方式          | 外方内圆/八角边框、角花、对称式布局            |
| 主体剪影 | 主体为实心剪影 + 内部镂空线 | 花卉/鸟兽外轮廓完整，内部用白线刻出结构          |

**关键认知：通用大模型不懂"细纹刻纸"四个字时会画成普通红色剪纸或日本切り絵，必须在提示词里把技法词拆开喂给它，并给参考图。**

## 1.5 迭代优化流程（每张图案的标准产线）

```
第1轮：用1.3.1模板+主体词出4张 → 判断风格是否到位（红白二值/细纹/边框）
  ├─ 风格不到位 → 换提示词或垫真实刻纸参考图（参考强度0.3），再来一轮
  └─ 风格到位、主体不像 → 保留风格，按1.3.3补辨识词，再来一轮
第2轮：从风格+主体都合格的图里挑构图最对称、底纹最均匀的1张
第3轮：后处理（见下）→ 入项目
```

**单张后处理（5 分钟，免费工具 Photopea.com 或 removebg）：**

1. removebg / Photopea 魔棒去除白底 → 导出**透明底 PNG**（贺卡合成时需要透明通道）
2. 色阶/阈值二值化，消除任何灰粉杂色（图像 → 调整 → 阈值，约 180\~210）
3. 画布统一为 **1024×1024 居中**，主体占画面 75% 左右
4. 命名入库：`public/patterns/{id}.png`（如 `japan-sakura.png`）
5. 修改 [patternData.ts](file:///c:/Users/zyx07/Desktop/trae_project/paper-cutting-h5/src/utils/patternData.ts)：为 Pattern 增加 `imageUrl?: string` 字段，选择页优先渲染图片、无图时回退 SVG

**效果验收标准（每张必须全过）：**

- [ ] 只有红、白（透明）两色，无灰粉杂色、无渐变
- [ ] 主体一眼可辨识（让不了解项目的人看 3 秒能说出是什么）
- [ ] 空白区域有细密底纹，不是大片纯白
- [ ] 主体无断连（红色实心区域不能被镂空白线切成孤岛，否则视觉上"碎掉"）
- [ ] 1024×1024 透明 PNG，文件 ≤ 500KB（tinypng.com 压缩一次）
- [ ] 手机上缩到 80px 缩略图时主体轮廓仍清晰

# 2. 草图 → 细纹刻纸风格图像的技术实现方案

## 2.1 技术原理：为什么现在的方案做不到

当前 [imageUtils.ts](file:///c:/Users/zyx07/Desktop/trae_project/paper-cutting-h5/src/utils/imageUtils.ts) 的 `applyPaperCutEffect` 流程是：灰度化 → Sobel 边缘检测 → 阈值描边 → 染成红色。它的输出本质是\*\*"照片描红线稿"**，而刻纸是**"红色实心剪影 + 内部镂空 + 几何底纹"\*\*——后者需要模型理解"哪里该留红纸、哪里该镂空、空白处补什么纹样"，属于生成式任务，确定性的像素算法无法完成。

正确的技术路线是 **图生图（img2img）+ 结构控制（ControlNet）+ 风格 LoRA/提示词 + 二值化后处理**：

```
用户草图
  → [预处理] 提纯为干净线稿
  → [ControlNet] 锁定构图/主体位置（Canny 或 Lineart）
  → [img2img] 在锁定结构上按"细纹刻纸"提示词+LoRA重绘
  → [后处理] 去底、二值化、碎点清理、连通性校验、补边框底纹
  → 透明PNG → 合成贺卡
```

## 2.2 可选技术栈对比

| 方案                   | 实现方式                                                         | 成本            | 效果              | 适合阶段       |
| -------------------- | ------------------------------------------------------------ | ------------- | --------------- | ---------- |
| ① 纯前端 Canvas（现状）     | 灰度+边缘+染红                                                     | 0             | 线稿，非刻纸          | 仅保底        |
| ② 云 API 图生图          | 即梦/通义/Replicate 图生图，草图直传 + 风格提示词                             | 按次/免费额度       | 较好，结构保留 70\~85% | **MVP 首选** |
| ③ 云 API + ControlNet | Replicate（SDXL/Flux + controlnet-canny/scribble）             | 约 ¥0.1\~0.5/张 | 好，结构保留 85%+     | 正式上线       |
| ④ 自建后端               | FastAPI + diffusers + SD1.5/SDXL + ControlNet + LoRA，GPU 服务器 | 服务器成本         | 最好、可批量可调        | 规模化        |
| ⑤ 人工出图               | 用户上传 → 运营人工用在线工具转（见第 4 章）                                    | 人力            | 最好、零开发          | 当前无预算时     |

## 2.3 模型选择（方案 ③/④）

- **结构控制**：ControlNet Canny（硬边缘，适合轮廓清楚的草图）或 Scribble（潦草手绘容忍度高）；线稿干净用 Lineart
- **生成底模**：SD1.5 + 国风/papercut LoRA（显存要求低、出图快）；追求质量用 SDXL/Flux
- **风格 LoRA**：Liblib 搜 "剪纸"、"paper cut"、"国风纹样"，选样例接近红白二值风格的，权重 0.6\~0.8
- **关键参数**：img2img 重绘强度（Denoising strength）**0.45\~0.65**——太低还是草稿味，太高主体会跑形；ControlNet 权重 0.7\~0.9

> 经验教训（来自同类项目实测）：草图转换必须在提示词中强制要求 "preserve composition, preserve subject position, same layout as reference"，负面词加入 "doodle, stick figure, simple lineart, minimal lines"；风格必须由参数分支明确指定，不能随机，否则结果会在"线稿/填色/完整重绘"之间漂移。

## 2.4 预处理流程（上传后、送模型前，前端即可完成）

1. **方向校正**：读取 EXIF orientation，沿用现有 `rotateImage`
2. **裁剪**：居中裁正方形，主体占 70\~80%
3. **尺寸归一**：长边 1024px（沿用 `resizeImage`，上限改 1024）
4. **去阴影提纯线稿**（关键，手机拍照有阴影）：
   - 转 Lab 取 L 通道，做自适应阈值（OpenCV `adaptiveThreshold`，blockSize 35, C 15）
   - 或简单法：色阶拉伸（最暗 5% 映射黑、最亮 5% 映射白）
5. **白底黑线反相为白线稿**备用，输出干净 PNG 送模型

## 2.5 后处理流程（模型出图后，Python 服务端或前端 Canvas 均可）

1. **去背景**：rembg 抠图，或直接按白阈值转 alpha（红白二值图甚至不需要 AI 抠图）
2. **强制二值化**：红色像素判定——将偏红通道保留为 #C41E3A，其余转透明；保证无杂色
3. **形态学清理**：开运算去掉 < 8px 的孤立红点（噪点），闭运算修补 < 3px 的断线
4. **连通性校验**（刻纸专业性的关键）：最大连通主体区域占比 < 40% 时报警（说明图案被镂空切碎），自动降低内部镂空密度重试一次
5. **底纹补齐（可选）**：主体外的大块空白区域，程序平铺一层细鱼鳞纹/回字纹 PNG 纹理（multiply 混合），让空图也有"细纹感"
6. **边框合成**：统一套一层预存的刻纸边框素材（可用第 1 章方法生成 1 个通用边框复用）
7. **导出**：1024×1024 透明 PNG，tinypng 级压缩

## 2.6 系统集成架构（正式版）

```
H5(React) ──上传草图+风格选项──▶ FastAPI 后端
                                  │
                  ┌───────────────┼────────────────┐
                  ▼               ▼                ▼
           预处理(Pillow/      推理(调云API 或    后处理(Pillow/
           OpenCV)            本地diffusers)     OpenCV/rembg)
                                  │
                                  ▼
                        透明PNG → 回传 H5
                                  │
                          前端 Canvas 合成贺卡 → 分享/保存
```

- 接口建议：`POST /api/sketch-to-papercut`（multipart 上传，返回任务 id）+ `GET /api/task/{id}` 轮询（推理 5\~20 秒，必须异步）
- 前端交互：上传后显示"刻纸师傅正在动刀…"进度动画，禁用重复提交；失败回退到现有 Canvas 滤镜版，保证流程不中断

## 2.7 草图转换验收标准

- [ ] 主体结构与草图一致（同一主体、同朝向、构图位置不变）——与草图并排对比
- [ ] 输出是红白二值实心剪影而非描边线稿
- [ ] 有内部镂空细节与底纹，远看是刻纸不是"红色贴纸"
- [ ] 主体不碎（连通性校验通过）
- [ ] 端到端耗时：云 API ≤ 20 秒；失败有明确提示与兜底
- [ ] 同一张草图生成 3 次，至少 2 次达到上述标准（稳定性）

| 用户上传草图 → **真正 AI 语义级**刻纸转换并秒回 | 浏览器内无法跑 SD 级模型；现有环境无 GPU 后端、无已配置的付费 API Key | 开通任一图生图 API（即梦/通义/Replicate）并写后端；或部署 GPU 服务 |

# 4. 人工操作落地指南（无后端/无 API 时完整可复现）

> 目标：不写一行后端代码，靠免费工具 + 固定流程，人工产出与 AIGC 自动化等价的效果。

## 4.1 生产 8 张国风图案（每张约 8\~12 分钟）

**工具准备（全部免费）：** 即梦 AI（jimeng.jianying.com）、Photopea（photopea.com，网页版 PS）、tinypng.com

**步骤：**

1. 即梦注册登录 → "AI 作图" → 文生图
2. 模型选最新通用模型，比例选 **1:1**，一次出 4 张
3. 粘贴 1.3.1 中文模板，把【主体】替换为 1.3.2 对应主体词
4. （第 2 轮起强烈建议）点"参考图"，上传项目 `png` 文件夹里的真实刻纸作品（如《松鹤延年》），参考强度调 **0.3\~0.4** —— 这一步决定出图是"细纹刻纸"还是"普通剪纸"
5. 生成后按 1.5 验收清单勾选；不合格按 1.3.3 改词重出，**不要凑合**
   8 张图共用同一张参考图、同一套提示词，风格自然统一
6. 选定的图下载（选无水印下载）
7. 打开 Photopea：
   - 魔棒工具点白底（容差 20，勾选连续）→ Delete 删除白底
   - `图像 → 调整 → 阈值`（约 190）彻底二值化
   - `图像 → 画布大小` 改为 1024×1024，居中
   - `文件 → Export as → PNG`（保留透明）
8. tinypng 压缩，命名为 `public/patterns/{id}.png`
9. 通知开发侧在 `patternData.ts` 补 `imageUrl: '/patterns/xxx.png'`

**验收：** 执行 1.5 的 6 项勾选清单。

## 4.2 把用户手绘草图人工转成刻纸（单张约 10\~15 分钟）

**场景：** 演示、比赛答辩、重点用户订单。用户草图通过现有"上传"入口拿到图后：

**第一步：清理草图（Photopea，3 分钟）**

1. 打开照片 → `图像 → 调整 → 去色`
2. `色阶（Ctrl+L）`：右侧白滑块左拉到 230、左侧黑滑块右拉到 25，去灰底、压黑线条
3. 裁剪为正方形，主体居中，导出 `sketch-clean.png`

**第二步：AI 图生图重绘（即梦，5 分钟）**

1. 即梦选"**图片生成 → 图生图**"，上传 clean 草图
2. 参考强度/相似度设 **50%\~60%**（太高是涂色、太低会跑形）
3. 提示词：

```
按参考图的构图和主体，重绘为中国乐清细纹刻纸风格的红色剪纸：
红色实心剪影，内部白色镂空线条，背景铺满鱼鳞纹与回字纹细密底纹，
传统方形边框和角花，仅中国红与纯白两色，平面，高对比度，无渐变无阴影，
保持与参考图相同的主体、朝向和构图位置
```

负面意图（若有负面词框）：线稿、涂鸦、简笔画、渐变、阴影、照片、文字、水印

1. 出 4 张 → 选**主体最像草图 + 底纹最细 + 不碎**的一张；跑形就降参考强度 10% 重出

**第三步：后处理（Photopea，3 分钟）**

1. 魔棒去白底 → 阈值二值化（同 4.1 第 7 步）
2. 放大检查：套索删掉孤立小红点碎渣；主体内必要的红色"连接桥"若被镂空切断，用 1\~2px 红色硬边画笔补桥
3. 空白太大的地方，可叠加一层提前备好的鱼鳞纹素材（正片叠底/降低不透明度手动刻感）
4. 导出 1024×1024 透明 PNG → tinypng 压缩

**第四步：回灌应用**

- 放入 `public/uploads/`（演示用），贺卡编辑器直接读取；或通过现有上传流程的"成品预览"位替换
- 合成贺卡、加祝福语、保存分享——闭环完成

**效果优化技巧：**

- 草图本身越**轮廓闭合、线条粗黑、背景干净**，转换越稳；引导用户用黑笔在白纸上画、光线均匀拍照（可在上传页加示例图）
- 人物/动物比花卉容易跑形，提示词补"对称构图、正面"能显著提高稳定性
- 所有图过一遍阈值二值化，是消除"AI 味"（灰红渐变）最有效的一步
- 建一个"提示词与成品对照库"（哪个主体用什么词、多少参考强度），越用越稳

**验收：** 执行 2.7 的 6 项标准；人工转换额外要求与草图并排时"主体能一眼对上"。

# 5. 各环节操作要点 / 注意事项 / 验收标准汇总表

| 环节    | 操作要点                                             | 注意事项                       | 验收标准                |
| ----- | ------------------------------------------------ | -------------------------- | ------------------- |
| 提示词编写 | 六段式：主体+风格+底纹+构图+双色+画质；主体辨识词单独强化                  | 只说"刻纸"不够，必须列具体底纹名词；不让模型写字  | 外行 3 秒认出主体与剪纸风格     |
| 参考图垫图 | 用项目内 6 张真实刻纸作品，强度 0.3\~0.4                       | 强度过高会照抄原作构图                | 风格像、构图为新主体          |
| 系列统一  | 同工具/同参考图/同模板；SD 固定 seed                          | 8 张分开在不同工具做必然风格漂移          | 8 张并排像一套作品          |
| 出图筛选  | 每主体 4 选 1，不合格重出不凑合                               | 警惕碎图、灰阶、切边、乱字              | 1.5 六项清单全过          |
| 去底二值化 | 魔棒去白 + 阈值 \~190 + 连通检查                           | 别用羽化边缘，刻纸边缘必须锐利            | 仅红/透明二色             |
| 资源规格  | 1024×1024 透明 PNG，≤500KB，居中                       | 体积过大会拖慢 H5 加载（目标首屏 <3s）    | 手机 80px 缩略图仍清晰      |
| 草图预处理 | 去色+色阶去阴影+裁正+1024                                 | 拍照阴影是转换失败的首要原因             | 线稿黑、底白净             |
| 图生图   | 参考强度 50\~60%，提示词强调保结构                            | 强度参数每偏 10% 结果差异巨大          | 主体/朝向/构图与草图一致       |
| 后处理   | 去碎点、补连接桥、必要时铺底纹套框                                | 主体被镂空切碎是最常见废片              | 主体连通面积 ≥40%         |
| 前端接入  | Pattern 加 imageUrl 字段，图片优先 SVG 回退；AI 转换异步化+进度+兜底 | 同步等待会 ANR；无 API 时必须能回退现有滤镜 | 全流程不中断、弱网可用         |
| 性能    | 素材压缩、懒加载、接口异步轮询                                  | 生成耗时 5\~20s 属正常            | 交互响应 <500ms，转换有进度反馈 |
| 合规    | AI 生成内容上线前人工审核；规避受版权保护的具体原作直接复刻                  | 垫图仅取风格，成品不得与名家作品构图雷同       | 人工审核通过              |
